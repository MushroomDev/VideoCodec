❓ 常见问题

点击问题展开答案。如果这里没有解决你的疑问，欢迎提交 Issue。

最低要求：

  • macOS 12.0 Monterey 及以上
  • Apple Silicon (M1 / M2 / M3 / M4) 或 Intel Mac
  • 200MB 可用磁盘空间

推荐配置：

  • macOS 14.0 Sonoma 及以上
  • Apple Silicon M2 及以上（获得最佳 VideoToolbox 硬件加速）

CodecFlow 对 Apple Silicon 做了原生优化，在 Apple Silicon 设备上性能最佳。Intel Mac 同样完全兼容。

CodecFlow 是通用二进制（Universal Binary），同时包含 ARM64 和 x86_64 架构。

在 Apple Silicon Mac 上以原生 ARM64 模式运行，不会通过 Rosetta 转译，可以获得最佳性能和 VideoToolbox 硬件加速。

通常有以下原因：

  1. 音轨未被选择：检查设置面板的"音频"标签页，确认已勾选要保留的音轨。
  2. 音频编码不兼容：某些源文件的音频编码（如 DTS / AC-3 / E-AC3）在目标容器中不被支持。建议输出时选择 AAC 编码。
  3. 源文件音轨问题：极少数情况下源文件本身音轨损坏。尝试用其他播放器（如 IINA）确认源音频是否正常。

如果问题仍然存在，请在输出格式中选择 MKV 容器搭配 AAC 音频编码，这是兼容性最高的组合。

画质下降通常是因为编码参数设置过低。建议：

  • 提高码率：在"视频设置"中调高目标码率。1080p 建议 8-12 Mbps，4K 建议 30-50 Mbps。
  • 使用 CRF 模式：切换到 CRF（恒定质量）模式，推荐值 18-23（数值越小质量越好）。
  • 选择更慢的预设：编码预设从“veryfast”切换到“medium”或“slow”可显著提升画质，代价是编码时间增加。
  • 保持原始分辨率：除非确有必要，否则不要修改分辨率。

专业提示：CRF 18 + slow 预设 ≈ 视觉无损，非常适合存档场景。

CodecFlow 支持以下字幕处理方式：

  • 保留内嵌字幕流：输出 MKV 容器时，可保留源文件的 SRT / ASS / PGS 字幕流。
  • 烧录硬字幕：将字幕永久嵌入视频画面，适合分享到不支持软字幕的平台。
  • 软字幕：MP4 容器支持 mov_text 字幕（兼容性一般），MKV 容器支持几乎所有字幕格式。

最佳兼容方案：输出 MKV 并保留原始字幕流，或烧录为硬字幕输出 MP4。

VideoToolbox 硬件加速在以下条件全部满足时自动启用：

  1. 设备为 Apple Silicon (M1/M2/M3/M4) 或 Intel Mac 支持 Quick Sync
  2. 输出编码选择 H.264 或 H.265 (HEVC)
  3. 在设置中开启"优先使用硬件加速"选项

硬件加速可提升 3-5 倍编码速度，同时大幅降低 CPU 占用和发热。注意：硬件编码的压缩率通常略低于纯软件编码（x264/x265），适合速度优先的场景。

有几种方式控制 CPU 占用：

  • 在设置中调整"并行任务数"，默认为自动（CPU 核心数），可手动降至 1-2。
  • 开启 VideoToolbox 硬件加速，将编码负载转移到专用硬件。
  • 使用更快的编码预设（ultrafast / superfast / veryfast），降低每帧编码复杂度。

CodecFlow 的任务调度器会自动平衡系统负载，你也可以在 Activity Monitor 中限制 App 的 CPU 优先级。

CodecFlow 使用行业标准的 AES-128 或 AES-256 加密方案：

  • AES-128：128 位密钥，速度较快，适合日常使用。
  • AES-256：256 位密钥，安全性更高，适合敏感内容。
  • 加密密钥和 IV（初始化向量）由用户自定义输入。
  • 加密后的视频需要通过相同密钥在 CodecFlow 或其他支持 AES 解密的播放器中打开。

⚠️ 注意：密钥丢失后将无法恢复视频内容。请妥善保管密钥，CodecFlow 不会以任何形式存储或上传你的密钥。

使用 AES 加密的 MP4/MKV 文件兼容以下播放器：

  • ✅ VLC Media Player
  • ✅ IINA (macOS)
  • ✅ mpv
  • ✅ 支持 AES 解密的命令行工具
  • ❌ QuickTime Player（不支持加密流）
  • ❌ Safari 内嵌播放器
